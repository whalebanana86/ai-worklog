# UI/UX 검토 (2026-10)

- **검토한 것**: `main`(v1.1.3) 앱을 지어낸 데모 기록(`--demo`)으로 띄웠다.
  - 화면: 한눈에 보기, 날짜별 기록, 모든 요청, 스킬·규칙, 프로젝트(날짜별·세션 탭), 세션, 설정, 보고서, AI 없음.
  - 조건: 창 크기 1440×900·980×760, 밝은 화면·어두운 화면, macOS 26.3.
- **견준 기준**: Apple 의 Liquid Glass 채택 문서와 HIG(재질·사이드바·툴바·차트·생성형 AI), macOS 27 발표 내용, 대시보드와 AI 기능 UX 자료. 출처는 맨 아래에 있다.
- 코드는 바꾸지 않았다. 이 문서는 제안이다.

## 1. 결론

**뼈대는 이미 최신이다.**
- 표준 부품 위에 서 있다: `NavigationSplitView` + 사이드바 검색, 툴바 가운데 기간 고르기, 오른쪽 버튼 묶음, `Form(.grouped)` 설정, `ContentUnavailableView` 빈 화면, Swift Charts.
- 그래서 배포본(GitHub Actions 가 Xcode 26.3·macOS 26 SDK 로 만든다)은 macOS 26 의 Liquid Glass 모습을 저절로 입는다. 사이드바와 툴바에 배경을 직접 칠한 곳도 없다.
- macOS 27(Golden Gate)의 바뀐 점(창 끝까지 닿는 사이드바, 통일된 툴바, 같은 창 모서리)도 표준 부품에 자동으로 적용된다고 발표됐다.

**모자란 것은 다듬기다.** 크게 갈아엎을 필요는 없다.
1. 화면마다 머리 구성이 달라서 일관성이 없다.
2. 프로젝트·세션 화면은 위쪽이 숫자 타일로 무거워, 핵심 내용이 첫 화면 아래로 밀린다.
3. 접근성 라벨이 하나도 없다. VoiceOver 로는 차트·도구 점·숫자 타일의 뜻이 전달되지 않는다.
4. 맥 앱다운 손놀림(우클릭 메뉴, 키보드로 목록 이동, 인스펙터)이 적다.
5. AI 요약에 "틀릴 수 있음" 안내와 되돌리기·고치기 수단이 없다.

## 2. 조사한 최신 흐름

### 2.1 Apple Liquid Glass (macOS 26 Tahoe, 2025)

Apple 의 "Adopting Liquid Glass" 문서와 HIG 에서 이 앱에 해당하는 규칙만 골랐다.

- **표준 부품을 쓰면 저절로 바뀐다.** 막대·시트·팝오버·컨트롤이 새 재질을 입는다. 최신 Xcode 로 빌드해 보는 것이 첫걸음이다.
- **유리는 탐색·컨트롤 층에만 쓴다.** "Don't use Liquid Glass in the content layer." 카드·목록 같은 내용에는 쓰지 않는다. 직접 만든 컨트롤에도 아껴 쓴다.
- **막대·사이드바에 직접 칠한 배경은 줄인다.** 시스템이 주는 유리와 스크롤 가장자리 효과를 가린다.
- **툴바**
  - 자주 쓰는 동작은 글 대신 기호로, 테두리 없는 시스템 기호를 쓴다.
  - 묶음은 많아야 3개다.
  - 창 제목은 15자 안쪽으로 쓰고, 앱 이름을 제목으로 쓰지 않는다.
  - 기호마다 접근성 라벨을 단다.
- **사이드바**
  - 단계는 2단계까지다.
  - 아이콘 색은 시스템 강조색을 따른다.
  - 맨 아래에는 중요한 정보·동작을 두지 않는다. 창을 옮기다 아래쪽이 가려지기 쉬워서다.
  - 숨기고 보일 수 있게 한다.
- **목록·폼**: 행 높이와 여백이 커졌다. 섹션 머리말은 제목식 대소문자를 쓴다.
- **사이드바 + 인스펙터**: 스플릿 뷰로 사이드바·본문·인스펙터를 구성하라고 권한다. 창 크기는 마음대로 바꿀 수 있어야 한다.
- **접근성**: 투명도 줄이기·움직임 줄이기·대비 높이기 설정에서 직접 만든 요소를 시험한다.

### 2.2 macOS 27 Golden Gate (WWDC26, 2026년 6월)

- 새 디자인이 아니라 다듬기다.
  - 유리 모습을 "아주 맑게~완전히 색칠"까지 고르는 슬라이더가 생겼다.
  - 툴바가 위쪽 전체를 덮는 통일된 서리 유리가 됐다.
  - 사이드바가 창 끝까지 닿는다.
  - 모든 창의 모서리 반경이 같아졌다.
  - 대비와 굴절이 고르게 바뀌었다.
- 이미 유리를 쓰는 앱에는 자동으로 적용된다고 발표됐다.
- SwiftUI 쪽 새 기능: 툴바 항목 보이기 우선순위, 좁을 때 저절로 접기, 늘 더보기 메뉴에 두는 배치. 좁은 창에서 무엇부터 숨길지 정할 수 있다.

### 2.3 데이터 화면(대시보드)

- 5초 안에 핵심을 알 수 있어야 하고, 가장 중요한 숫자를 먼저 둔다.
- 숫자에는 맥락을 붙인다(지난 기간보다 늘었나 줄었나). 맥락 없는 숫자는 잡음이다.
- 차트는 제목·설명으로 무엇을 보여 주는지 먼저 말하고, 핵심 메시지를 글로 요약한다 (HIG 차트).
- 핵심 정보를 보려고 마우스를 올리거나 눌러야 하면 안 된다.
- 모든 차트는 VoiceOver 로 읽혀야 한다. 색만으로 계열을 구분하지 않는다.

### 2.4 AI 기능

HIG 생성형 AI 지침, AWS Cloudscape, IBM Carbon for AI 에서 공통으로 말하는 것이다.

- AI 가 만든 글에는 AI 라는 표시를 단다. AI 글과 사람 글이 섞인 화면일수록 중요하다.
- 무엇을 할 수 있고 못 하는지 알린다. 그럴듯하게 틀릴 수 있음(환각)도 알린다.
- 결과 옆에 고치기·되돌리기·다시 만들기를 둔다. 고친 것이 반영됐음을 알린다.
- 결과에 대한 의견을 남길 수 있게 한다.
- 만드는 동안에는 "처리 중…"보다 구체적인 진행 문구를 쓴다.
- AI 가 없거나 꺼도 앱은 쓸 수 있어야 한다.

## 3. 지금 앱 점검

### 3.1 공통

**잘된 점**
- 표준 스플릿 뷰·툴바·검색이라 macOS 26 유리 모습을 그대로 받는다. macOS 27 변경도 자동으로 따라간다.
- 툴바 묶음은 뒤로 · 기간 · 필터/보고서/새로 고침, 3개다 (HIG 의 3개 이하).
- 어두운 화면, 3개 언어, 도구 색 사용자 지정(색약 검증 기본 팔레트)이 있다.
- 빈 화면을 표준 `ContentUnavailableView` 로 그린다.
- 내용 카드에는 유리를 쓰지 않는다 (HIG 대로).

**고칠 점**

| # | 내용 | 근거 |
|---|---|---|
| A | **화면 머리가 제각각이다.** 한눈에 보기·프로젝트·스킬·세션은 본문에 큰 제목(28pt)이 있다. 날짜별 기록·모든 요청은 큰 제목 없이 목록부터 시작한다. 프로젝트 화면은 창 제목·부제(`todo-app`, `~/Projects/todo-app`)와 본문 큰 제목·경로가 같은 말을 두 번 한다. | 일관된 탐색 구조 (Liquid Glass 문서) |
| B | **모든 요청 화면의 첫 줄이 툴바 밑에서 시작한다.** 캡처에서 첫 행이 유리 아래로 들어가 흐리게 보였다. 위 여백이나 안전 영역을 확인해야 한다. 스크롤 위치가 남아 있던 것일 수도 있어 다시 봐야 한다. | 안전 영역·스크롤 가장자리 효과 |
| C | **필터 기호가 테두리 있는 기호다** (`line.3.horizontal.decrease.circle`, 켜지면 `.fill`). | "Prefer system-provided symbols without borders" |
| D | **사이드바 맨 아래에 상태 줄("09:31 기준 · 보관함 세션 12개")과 설정 톱니가 있다.** 설정은 ⌘, 로도 열리니 괜찮다. 상태 정보는 아래가 가려지면 안 보인다. | "Avoid putting critical information or actions at the bottom of a sidebar" |

| F | **글자 크기를 숫자로 박은 곳이 6곳이다** (큰 제목 28pt·숫자 타일 24pt·불러오는 화면 아이콘 40pt). 시스템 글꼴 스타일을 따르지 않는다. | 표준 크기·간격 쓰기 |
| G | 기여자 쪽 Xcode 15.4 빌드는 옛 SDK 라 유리 없는 옛 모습이다. 배포본은 CI(Xcode 26.3)라 괜찮다. 다만 `glassEffect` 같은 새 API 를 쓰면 Xcode 15.4 빌드가 깨지니, `#if compiler(>=6.2)` 와 `if #available(macOS 26, *)` 로 감싸야 한다. | 빌드 호환 |

### 3.2 화면별

**한눈에 보기**
- 잘됨:
  - 맨 위 한 줄 요약("프로젝트 4곳에서 AI 에게 36번 요청하고, 약 3시간 54분 함께 작업했어요")이 5초 규칙에 맞는다.
  - 차트에 범례와 도구 색이 있다.
  - 넓은 창에서 카드 두 장이 반씩 나뉜다.
- 고칠 점:
  - 숫자 타일 6개에 맥락이 없다. 지난 같은 기간보다 얼마나 늘었고 줄었는지가 없다.
  - 히트맵과 막대 차트를 VoiceOver 로 읽을 수 없다 (E).

**날짜별 기록**
- 잘됨: 날짜 머리 → 도구 색 세로 줄 → 요청 → 결과 한 줄 → 도구·프로젝트·파일 수로 훑기 좋다.
- 고칠 점:
  - 화면 큰 제목이 없다 (A).
  - "이날 보고서" 버튼이 날짜마다 반복된다. 날짜 머리에 마우스를 올릴 때만 보이게 하거나 우클릭 메뉴로 옮길 만하다.
  - 날짜 머리가 스크롤할 때 위에 붙어 있는지는 확인하지 못했다(`List(.inset)` + `Section` 머리). 붙어 있지 않다면 긴 목록에서 지금 어느 날인지 놓친다.

**모든 요청**
- 잘됨: 밀도가 높고, 시각·프로젝트·세션 제목·파일 수가 한 줄에 정리돼 있다.
- 고칠 점:
  - B(첫 줄이 툴바 밑).
  - AI 결과 미리보기가 없다. 날짜별 기록에는 있다.
  - 키보드로 위아래 이동, Return 으로 열기, 우클릭 메뉴(요청 복사·세션 열기)가 없다. 키보드 단축키는 메뉴 명령 10개뿐이다.

**프로젝트**
- 잘됨:
  - AI 요약 상자에 "AI 요약 · Claude Code" 출처가 붙어 있다.
  - "요약한 뒤로 요청이 1개 더 생겼어요. 손을 떼고 30분이 지나면(09:49쯤) 이어서 요약해요" 같은 구체적인 안내가 있다.
  - "다시 요약·이어서 요약·다시 시도"가 있다.
  - AI 가 없을 때의 안내가 친절하다.
  - AI 기능 지침에 잘 맞는다.
- 고칠 점:
  - **위쪽이 무겁다.** 큰 제목 → 경로 → 버튼 3개(Finder·터미널·경로 복사) → 숫자 타일 5개 → 30일 차트 → 탭 순서다. 이 화면의 핵심인 날짜별 AI 요약은 1440×900 창에서 첫 화면 맨 아래에 겨우 걸친다.
  - 버튼 3개는 툴바나 `…` 메뉴, 프로젝트 이름의 우클릭 메뉴로 옮길 수 있다.
  - 숫자 타일은 한 줄 요약 글로 줄일 수 있다.
  - AI 요약에 "AI 가 만든 요약이라 틀릴 수 있어요" 안내가 없다. 이전 요약으로 되돌리기, 직접 고치기, 좋다/아쉽다 의견도 없다.

**세션**
- 잘됨: 도구·스킬 꼬리표, 프로젝트·브랜치·시간 줄, "이어서 작업하기" 버튼, 요청 → 고친 파일 → AI 답 한 줄 구성이 좋다.
- 고칠 점: 숫자 타일 6개(두 줄)가 대화보다 먼저 나와서, 대화가 첫 화면 중간부터 시작한다. 숫자·도구·모델은 인스펙터(오른쪽 패널, `.inspector`)로 옮기고 본문은 대화부터 시작할 만하다.

**설정·빈 화면**: 표준 `Form(.grouped)` 와 `ContentUnavailableView` 라 지침에 맞는다. 고칠 것이 거의 없다.

## 4. 제안 (중요한 순서)

**P1. 작게 고치고 효과가 큰 것**
1. **접근성 라벨 달기** (E)
   - 도구 점: "Claude Code·Codex" 처럼 읽히게 한다.
   - 숫자 타일: 이름과 값을 한 요소로 묶는다.
   - 차트: 제목과 한 줄 요약을 단다 (Swift Charts 의 `accessibilityChartDescriptor`·Audio Graphs).
   - 히트맵 칸: "화요일 14시 요청 3개" 처럼 읽히게 한다.
2. **화면 머리 통일** (A): 모든 화면을 같은 꼴(큰 제목 + 한 줄 요약)로 맞춘다. 또는 창 제목에 맡기고 본문 큰 제목을 뺀다. 프로젝트 화면의 이름·경로 중복은 한쪽만 남긴다.
3. **글자 크기를 글꼴 스타일로** (F): `.largeTitle`·`.title` 등으로 바꿔 시스템 설정을 따르게 한다.
4. **모든 요청 첫 줄 확인** (B): 처음 열 때와 스크롤 뒤 모두 첫 행이 툴바 아래에서 시작하는지 본다.
5. **필터 기호** (C): 테두리 없는 `line.3.horizontal.decrease` 로 바꾼다. 켜진 상태는 강조색이나 작은 점으로 알린다.

**P2. 구조 다듬기**

6. **프로젝트·세션 화면 위쪽 가볍게**: 동작 버튼은 툴바나 메뉴로 옮긴다. 숫자는 한 줄 요약 글로 바꾸고, 자세한 숫자·도구·모델은 인스펙터(⌥⌘I)에 둔다. 핵심 내용(날짜별 AI 요약, 대화)이 첫 화면에 오게 한다.
7. **숫자에 맥락**: 한눈에 보기 숫자 옆에 지난 같은 기간 대비 증감(▲12% 같은)을 붙인다.
8. **맥다운 손놀림**
   - 목록 행 우클릭 메뉴: 요청 복사, 세션 열기, Finder, 터미널, 이어서 작업하기.
   - 키보드: 위아래로 이동하고 Return 으로 연다.
   - 날짜 머리는 스크롤해도 위에 붙어 있게 한다.
   - 사이드바 맨 아래 상태 정보는 툴바 부제나 새로 고침 버튼 도움말로 옮긴다 (D).
9. **AI 요약 신뢰 장치**
   - 처음 한 번 "AI 가 만든 요약이라 틀릴 수 있어요"를 알린다.
   - 이전 요약으로 되돌리기(보관함에 지난 요약 하나를 남긴다)를 둔다.
   - 요약을 직접 고칠 수 있게 하고, 고친 것은 다시 요약할 때 덮지 않는다.

**P3. 고를 거리**

10. **macOS 26 이상에서만 유리 효과**: 떠 있는 작은 알림(지금 `.regularMaterial` 캡슐)을 `glassEffect` 로 바꾼다. Xcode 15.4 빌드를 지키려면 G 처럼 컴파일러 조건으로 감싼다.
11. **빠른 열기(⌘K)**: 프로젝트·세션을 이름으로 바로 연다. 맥 생산성 앱에 흔한 패턴이지만 Apple 표준 부품은 아니다. 지금 사이드바 검색을 키우는 쪽이 더 가볍다.
12. **macOS 27 대비**: Xcode 27 로 빌드해 사이드바가 창 끝까지 닿을 때 카드 여백이 괜찮은지 본다. 툴바 항목 우선순위로 좁은 창에서 숨길 순서를 정한다(기간 고르기는 남기고 새로 고침부터 접기).

**하지 말 것**
- 카드·목록 같은 내용에 유리 효과를 쓰지 않는다.
- 툴바·사이드바에 배경색을 칠하지 않는다.
- 툴바 기호에 여러 색을 쓰지 않는다.
- 창 제목에 앱 이름을 쓰지 않는다 (지금도 쓰지 않는다).

## 5. 확인하지 못한 것

- 키보드 탐색과 VoiceOver 는 직접 써 보지 않았다 (자동 조작 권한이 없다). E 는 코드 검색 결과에 기댄 판단이다.
- 투명도 줄이기·대비 높이기·움직임 줄이기 설정에서의 모습은 시스템 설정을 바꾸지 않아 보지 못했다.
- macOS 27 에서는 보지 못했다 (이 맥은 26.3).
- 날짜 머리 고정 여부(3.2)와 모든 요청 첫 줄 문제(B)는 캡처 한 장으로 본 것이라 다시 확인해야 한다.
- 웹 자료 중 대시보드·AI UX 글 일부는 업체 블로그라, 숫자 통계는 쓰지 않고 공통된 원칙만 옮겼다.

## 6. 진행 상황 (2026-10-21, `uiux-review` 브랜치)

대화의 "고칠 점" 2·3·4번을 진행했다. 1번(접근성 라벨)과 P3 는 아직이다.

| 항목 | 한 것 |
|---|---|
| 화면 머리 통일 (A) | 모든 화면이 같은 `PageHeader`(큰 제목 + 한 줄 요약)를 쓴다. 날짜별 기록·모든 요청에도 머리가 생겼다. 창 제목은 "어디인지 + 기간"으로 맞췄다(프로젝트·세션 화면 부제도 기간). 프로젝트 이름·경로 중복을 없앴다. |
| 프로젝트·세션 위쪽 가볍게 + 인스펙터 | 숫자 타일을 머리의 한 줄 요약으로 바꾸고, 자세한 숫자는 오른쪽 정보 패널(툴바 버튼·⌥⌘I, 연 상태 기억)로 옮겼다. 프로젝트의 Finder·터미널·경로 복사는 `…` 메뉴·오른쪽 클릭·정보 패널로 옮겼다. |
| 지난 기간 대비 | 한눈에 보기 숫자 타일 6개에 "▲ 12% · 그 전 30일 대비"를 붙였다. "지금까지"끼리 견준다(오늘 오전 ↔ 어제 이맘때). |
| 오른쪽 클릭·키보드 | 날짜별 기록·모든 요청 목록은 화살표로 고르고 Return(또는 두 번 누르기)으로 연다. 세션 줄(목록·최근 작업·프로젝트 세션·날짜 카드)과 사이드바 프로젝트에 오른쪽 클릭 메뉴를 달았다. |
| AI 요약 신뢰 장치 | "· 틀릴 수 있어요" 표시, `…` 메뉴(고치기·전 요약으로 되돌리기·요약 복사), 고치기 창을 넣었다. 고치거나 되돌린 요약은 새 요청이 생겨도 저절로 바꾸지 않는다(버튼으로만). 바로 전 판은 보관함에 남는다. |
| 글자 크기 (F) | 숫자로 박은 크기 6곳을 `.largeTitle`·`.title` 등 글꼴 스타일로 바꿨다. |
| 필터 기호 (C) | 평소엔 테두리 없는 `line.3.horizontal.decrease`, 거르는 중엔 채운 원 기호. |
| 모든 요청 첫 줄 (B) | 머리가 생기면서 첫 줄이 툴바 밑에서 시작하지 않는다(캡처로 확인). |
| 차트 마우스 띠 | 7일·90일에서도 막대와 같은 너비로 그린다 (고정 두께 선 → 막대 비율 사각형). |
| 패널 너비 | 사이드바 최대 480pt, 정보 패널 최대 420pt (둘 다 최대여도 가장 작은 창 960pt 안). 본문은 최소 너비를 고집하지 않아 패널을 넓혀도 창 밖으로 밀리지 않는다. 제한을 아예 없애면 정보 패널이 창 밖으로 폭주하고, 화면 상태로 계산하면 끌 때 AppKit 제약 계산이 끝나지 않아 크래시가 나서 고정값으로 했다. |

확인하지 못한 것:
- 화살표·Return·오른쪽 클릭과 고치기 창은 직접 눌러 보지 못했다 (자동 조작 권한이 없다).
- 필터 켜짐 표시는 캡처 때 창이 비활성이어서 모양 변화만 코드로 확인했다.
- README 그림(`docs/screenshots`)은 아직 예전 화면이다.
